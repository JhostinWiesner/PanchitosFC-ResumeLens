# Stage 2 --- Formal Design of the Normalization Transducer

## 1. Purpose and Scope

Stage 2 receives the skills extracted by Stage 1
(`ExtractedData.skills_raw`) and transforms each recognized form into the
canonical name defined by the shared catalog. Forms that are not
recognized are retained in `unrecognized`.

Normalization is global: it does not depend on the selected professional
profile. Sorting by category and profile is performed
later, in the `order()` operation.

This document describes the formal design of the transducer. It does not yet define
the implementation of `core/normalization.py`.

## 2. Normalization Before FST Input

Before processing a token, `normalize_text()` from
`core/text.py` is applied. According to the current code, this function:

1.  applies Unicode NFKC normalization;
2.  converts the text using `casefold()`;
3.  collapses sequences of whitespace and removes whitespace at the beginning and
    end.

Therefore, differences between uppercase and lowercase letters are resolved
**before** entering the transducer. For example, `Python`, `PYTHON`, and
`python` are converted to `python`.

`normalize_text()` does not remove punctuation. Therefore, `node.js`, `nodejs`, and
`node` are different forms and are recognized only if they appear as aliases
or variants generated by the catalog.

## 3. Alphabets

Let (C) be the catalog loaded through `Catalog`, and let

\[ S = `\operatorname{spellings}`{=tex}(C) \]

the map returned by `Catalog.spellings()`. Each key in (S) is an
already normalized input form, and each value is its canonical name.

### 3.1 Input Alphabet (`\Sigma`{=tex})

The input alphabet is derived from the characters that appear in the
keys of `spellings()`:

\[ `\Sigma`{=tex}= {, a `\mid`{=tex}`\exists`{=tex}s
`\in`{=tex}`\operatorname{dom}`{=tex}(S), a
`\text{ is a character of }`{=tex} s,}. \]

Thus, the transducer consumes recognized forms character by
character. (`\Sigma`{=tex}) is not the set of complete technologies:
it is the set of symbols that can appear in their
normalized forms.

### 3.2 Output Alphabet (`\Gamma`{=tex})

The output alphabet is the set of canonical names in the catalog:

\[ `\Gamma`{=tex}= {,q.`\text{canonical}`{=tex} `\mid`{=tex}q
`\in`{=tex}C,}. \]

Each canonical name is considered **a single output symbol**, even if
its textual representation contains multiple letters or underscores. For
example, `SCIKIT_LEARN` is a single symbol of (`\Gamma`{=tex}), not a sequence of eleven output symbols.

### 3.3 Empty Output

We use (`\varepsilon`{=tex}) to indicate that a transition does not
yet emit an output symbol. The canonical output is emitted when
the last character of a recognized form is consumed.

## 4. Construction Rule: States as Prefixes

For an input form (s), its prefixes include the empty string
(`\varepsilon`{=tex}), every proper prefix, and the complete form. For
example, the prefixes of `py` are:

\[ `\varepsilon`{=tex}, p, py. \]

For a set of forms (L), the state set of the individual transducer
is defined as:

\[ Q_L = {,p `\mid`{=tex}p
`\text{ is a prefix of some form }`{=tex} s `\in`{=tex}L,}. \]

The initial state is the empty prefix:

\[ q_0 = `\varepsilon`{=tex}. \]

The input transition is defined by character concatenation. If
(p) is a prefix and (a`\in`{=tex}`\Sigma`{=tex}), a transition exists
from (p) to (pa) when (pa) is also a prefix of some form
in the set:

\[ `\delta`{=tex}(p,a)=pa `\quad`{=tex}`\text{if }`{=tex}
pa`\in`{=tex}Q_L. \]

The final states are exactly the recognized complete forms:

\[ F_L = L. \]

Consequently, reaching a state that represents a proper prefix is not
enough to accept the token: the input must end in a state that
represents a complete form.

### 4.1 Output Function

For the transducer associated with canonical name (c), let (L_c) be the set of
forms in `spellings()` whose value is (c). The output function for each
transition is defined as follows:

\[ `\lambda`{=tex}\_c(p,a)=

```{=tex}
\begin{cases}
c & \text{si } pa\in L_c,\\
\varepsilon & \text{en otro caso.}
\end{cases}
```
\]

That is, the transition that completes a recognized form emits the
canonical symbol; transitions that only advance through a prefix
emiten (`\varepsilon`{=tex}).

**Construction condition:** this rule requires that, if a complete form
is also a prefix of a longer form, both forms
belong to the same canonical name. If the catalog allows a complete form
to be a prefix of another form associated with a different canonical name, the canonical name must not
be emitted upon reaching that prefix through a transition:
the output would have to be deferred until the actual end of the input is known.
The current `Catalog` validation detects identical forms assigned to
different canonical names, but it does not explicitly validate this prefix
condition.

## 5. Formal Seven-Tuple

The following convention is used:

\[
T=(Q,`\Sigma`{=tex},`\Gamma`{=tex},`\delta`{=tex},q_0,F,`\lambda`{=tex})
\]

where (Q) is the set of states, (`\Sigma`{=tex}) the input alphabet,
(`\Gamma`{=tex}) the output alphabet, (`\delta`{=tex}) the transition
function, (q_0) the initial state, and (F) the final states
y (`\lambda`{=tex}) the output function.

To avoid manually listing dozens of states, in each example
(Q) is defined as the complete set of prefixes of the specified forms
y (`\delta`{=tex}) using the prefix rule from Section 4. These
definitions specify all states and all valid transitions
of the transducer.

### 5.1 Example A: `PYTHON` --- a single word

In the shared catalog, the automatic variants of `PYTHON` are generated from a single-word name. The automatic forms
result in `python`. The catalog may also contain
additional aliases for this canonical name; the definitive set is always
obtained from `Catalog.spellings()`.

Let:

\[ L\_{`\text{PYTHON}`{=tex}} = {s
`\in`{=tex}`\operatorname{dom}`{=tex}(S)
`\mid`{=tex}S(s)=`\text{PYTHON}`{=tex}}. \]

The tuple is:

-   **(Q):** all prefixes of the forms in
    (L\_{`\text{PYTHON}`{=tex}}), including the empty string.
-   **(`\Sigma`{=tex}):** all characters present in the forms
    of (L\_{`\text{PYTHON}`{=tex}}).
-   **(`\Gamma`{=tex}):** the canonical names in the catalog; the symbol
    emitted by this transducer is `PYTHON`.
-   **(`\delta`{=tex}):** (`\delta`{=tex}(p,a)=pa) when (pa) is a
    prefijo of a form of (L\_{`\text{PYTHON}`{=tex}}); there is no
    transition otherwise.
-   **(q_0):** (`\varepsilon`{=tex}).
-   **(F):** the complete forms of (L\_{`\text{PYTHON}`{=tex}}).
-   **(`\lambda`{=tex}):** emits `PYTHON` when completing a form in
    (L\_{`\text{PYTHON}`{=tex}}); on all other transitions it emits
    (`\varepsilon`{=tex}).

For the form `python`, the path is:

\[ `\varepsilon`{=tex}`\xrightarrow{p}`{=tex} p `\xrightarrow{y}`{=tex}
py `\xrightarrow{t}`{=tex} pyt `\xrightarrow{h}`{=tex} pyth
`\xrightarrow{o}`{=tex} pytho `\xrightarrow{n}`{=tex} python. \]

The last transition emits `PYTHON`, and `python` is a final state.

## 6. Determinism and Functionality

### 6.1 Determinism

The transducer built as a prefix trie is deterministic because,
from a state (p), for an input character (a), there is at most
one next state: the prefix (pa). There are no two outgoing transitions
for the same state-character pair.

### 6.2 Functionality

A transducer is functional if an accepted input cannot produce
two different outputs. The catalog builds a map from normalized forms
to canonical names and raises `CatalogError` if the same form is
assigned to two different canonical names. Consequently, each form
recognized by `spellings()` has a single associated canonical name.

The functionality of the global union is preserved if the global construction
respects this uniqueness and correctly resolves
shared prefixes. The current validation checks collisions between complete forms,
but does not explicitly check conflicts where a complete form
is a prefix of another form belonging to a different canonical name; this
condition must be considered when building and testing the transducer.

## 7. Global Union of the Transducers

For each canonical name (c), an individual transducer (T_c) is defined
from the set (L_c). The set of individual transducers is:

\[ `\mathcal{T}`{=tex}={T_c `\mid`{=tex}c`\in`{=tex}`\Gamma`{=tex}}. \]

The goal of the global union is to recognize all forms in
`Catalog.spellings()` and emit the canonical name that the map associates with each
form:

\[ S(s)=c `\implies`{=tex}T\_{`\mathrm{global}`{=tex}}(s)=c. \]

The union must cover exactly the domain of the map:

\[ L\_{`\mathrm{global}`{=tex}}=`\operatorname{dom}`{=tex}(S). \]

### 7.1 Conceptual Construction

1.  Retrieve `spellings()` from the validated catalog.
2.  Group the forms by canonical name to define the
    individual transducers.
3.  Combine paths with shared prefixes into a reduced global
    structure.
4.  Mark complete forms as final and associate each one with its
    canonical symbol.
5.  Check that no form is assigned to more than one canonical name and that there are no
    output errors caused by shared prefixes.

A naive union of independent transducers may retain multiple
initial states or duplicate paths. Therefore, if the
global result is required to be deterministic, the final construction must merge
common prefixes or apply an equivalent operation that produces a
deterministic global trie. The word "union" describes the combination of
the languages and their output mappings; reduction is
necessary to obtain the desired deterministic representation.

## 8. Required Diagrams

The documentation and submission must include two diagrams:

1.  **Individual diagram:** a transducer for a single canonical name,
    with `PYTHON` recommended because it is easy to read. States represent
    prefixes; transitions consume characters; the transition that
    completes the form emits the canonical name.
2.  **Reduced global diagram:** a simplified representation of the
    union, with common prefixes merged and final forms
    associated with their canonical names. Due to the size of the catalog, this
    diagram should show the reduced structure or a representative
    section, not necessarily every transition for each
    technology.

The labels must distinguish input and output. A transition can
be represented as `character / output`; when no output is emitted, use
puede usar `carácter / ε`. The transition that completes a form must
show the emitted canonical symbol.
